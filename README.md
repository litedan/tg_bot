# Telegram RAG-агент

Бот ищет ответы в локальной базе знаний (`knowledge.txt`) и в интернете,
самостоятельно выбирая инструменты через tool-calling LLM.

## Как это работает

1. Пользователь задаёт вопрос в Telegram.
2. Агент (`agent.py`) отправляет вопрос модели вместе с описанием инструментов.
3. Модель вызывает `search_knowledge` (retrieval + rerank, запрос автоматически
   переписывается с учётом диалога), `web_search` (DuckDuckGo) и `read_page`
   (чтение полного текста страницы по URL), по необходимости несколько раз.
4. Агент нумерует источники `[1]`, `[2]`, ... и просит модель опираться на них.
5. В ответ добавляется блок «Источники», а история диалога сохраняется в
   `state/history.json`.

## Состав проекта

| Файл | Назначение |
|---|---|
| `bot.py` | Telegram-слой: команды, разбивка длинных ответов, «печатает» |
| `agent.py` | Агентный tool-loop, системный промпт, история |
| `input_layer.py` | Входной слой: невидимые символы, длина запроса, лимит частоты |
| `prompt_layer.py` | Сборка запроса: защита секретов и разметка чужого текста как данных |
| `tools.py` | Инструменты `search_knowledge`, `web_search` и `read_page`, реестр источников |
| `rag.py` | Chroma + E5 embeddings + cross-encoder rerank, авто-переиндексация |
| `config.py` | Все настройки из `.env` |
| `knowledge.txt` | База знаний |

## Слои безопасности

### Вход (`input_layer.py`)

Сообщение пользователя проходит проверки до вызова LLM:

- Unicode-нормализация NFKC и удаление невидимых символов (zero-width,
  bidi-управляющие, variation selectors, управляющие последовательности);
- блокировка «контрабанды», если невидимых символов слишком много
  (`INPUT_INVISIBLE_MAX_RATIO` при длине от `INPUT_INVISIBLE_MIN_CHARS`);
- ограничение длины запроса (`INPUT_MAX_CHARS`, по умолчанию 4000);
- лимит частоты по пользователю: скользящее окно `INPUT_RATE_LIMIT`
  сообщений за `INPUT_RATE_WINDOW` секунд.

### Сборка запроса (`prompt_layer.py`)

- реальные секреты (`OPENROUTER_API_KEY`, `BOT_TOKEN` и переменные с
  `KEY`/`TOKEN`/`SECRET`/`PASSWORD` в имени) вырезаются из системного промпта
  и из ответа модели;
- в системный промпт добавляется одноразовый canary-секрет, а финальный ответ
  проверяется на его утечку и при необходимости редактируется;
- текст результатов инструментов (фрагменты базы знаний, сниппеты веб-поиска,
  прочитанные страницы) оборачивается в `<data source="...">...</data>`;
  модель явно предупреждена, что это данные, а не инструкции. Закрывающие теги
  внутри внешнего текста экранируются, чтобы он не мог выйти из своего блока.

## Запуск

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# заполнить .env по образцу .env.example
python bot.py
```

Проверка без Telegram:

```powershell
python agent.py "Кто управляет Цитаделью Риков?"
python agent.py            # только состояние индекса
```

## Команды бота

- `/reset` — очистить историю диалога
- `/status` — состояние индекса, модель, веб-поиск
- `/help` — справка

## Индекс

Индекс пересобирается автоматически, если изменился `knowledge.txt` или модель
эмбеддингов. Отпечаток корпуса хранится в
`chroma_db/ru_knowledge_base_v2.manifest.json`.

## Важно про бесплатные модели OpenRouter

У бесплатных моделей лимит **50 запросов в день** на аккаунт, а общий пул
провайдера бывает перегружен (ошибка 429). Бот реагирует так:

1. Каждый запрос к LLM повторяется до `LLM_RETRIES` раз с экспоненциальной паузой
   (учитывается `Retry-After` от провайдера).
2. Если после ретраев основная модель недоступна, продолжается резервной
   `OPENROUTER_FALLBACK_MODEL` (если задана в `.env`).
3. Пользователю в Telegram приходит понятное сообщение вместо «ошибки».

Агент делает несколько запросов на один вопрос (решение + инструменты +
финальный ответ), поэтому при активном использовании дневной лимит расходуется
быстро. Варианты: подождать сброса лимита, добавить кредиты (от $10 откроет
1000 бесплатных запросов в день) или указать дешёвую платную tool-capable
модель в `OPENROUTER_MODEL`.
